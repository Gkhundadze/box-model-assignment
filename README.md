# CSS Box Model-ის ვიზუალური პრეზენტაცია (Content-Box vs Border-Box)

## მიზანი

სიღრმისეულად და პრაქტიკულად გაიაზრო, როგორ მუშაობს CSS-ის ერთ-ერთი ყველაზე მნიშვნელოვანი ფუნდამენტი — **Box Model** (`content`, `padding`, `border`, `margin`) და რა განსხვავებაა `box-sizing: content-box`-სა და `box-sizing: border-box`-ს შორის.

დავალების დასრულების შემდეგ ზუსტად გეცოდინება, რატომ „იბერება“ ელემენტები მოულოდნელად და როგორ აირიდო თავიდან გაფუჭებული განლაგება (Broken Layout).

---

## იდეა და კონტექსტი

წარმოიდგინე, რომ ქმნი **ვიზუალურ საგანმანათლებლო პრეზენტაციას / Cheat-Sheet-ს** დამწყები დეველოპერებისთვის. შენი მიზანია, მშრალი თეორიის ნაცვლად, ერთ ლამაზ და გასაგებ ვებგვერდზე თვალსაჩინოდ აჩვენო და აუხსნა მნახველს, რა ხდება „კულისებში“, როდესაც ბრაუზერი ელემენტის ზომებს ითვლის.

> **მნიშვნელოვანია:** დავალება სრულდება **მხოლოდ სუფთა HTML-ითა და CSS-ით**.

---

## ძირითადი მოთხოვნები

- **სემანტიკური HTML:** გამოიყენე `<header>`, `<main>`, `<section>`, `<h2>`, `<p>` და სხვა შესაბამისი ტეგები.
- **სექციებად დაყოფა:** თითოეული ნაწილი გამოყავი ცალკე `<section>` ტეგით და მიანიჭე მკაფიო სათაური.
- **ვიზუალური თვალსაჩინოება:** გამოიყენე ფერები, ჩარჩოები (`border`) და დაშორებები ისე, რომ მომხმარებელმა თვალითვე მარტივად აღიქვას სხვაობა.
- **ფაილების ორგანიზება:** HTML და CSS დაწერე ცალ-ცალკე ფაილებში (`index.html` და `style.css`).

---

## დავალების ეტაპები (ნაბიჯ-ნაბიჯ)

### ნაწილი 1 — შესავალი (Hero სექცია)

1. შექმენი გვერდის სათაურის სექცია (`<header>`).
2. დაწერე მთავარი სათაური (მაგალითად: *„CSS Box Model — როგორ ითვლის ბრაუზერი ზომებს?“*).
3. დაამატე 1-2 წინადადებიანი მოკლე და გასაგები შესავალი, თუ რატომ არის Box Model ვებდეველოპმენტის საფუძველი.

### ნაწილი 2 — Box Model-ის ანატომია (4 შრის ვიზუალიზაცია)

1. შექმენი სექცია სათაურით: **„Box Model-ის 4 შრე“**.
2. ააწყვე ვიზუალური ბარათი ან დიაგრამა, სადაც ნაჩვენები იქნება ელემენტის ოთხივე კომპონენტი (შეგიძლია გამოიყენო ერთმანეთში ჩასმული ბლოკები ან განსხვავებული ფერები, ბრაუზერის DevTools-ის მსგავსად):
   - **Content:** შიგთავსი (ტექსტი, სურათი).
   - **Padding:** შიდა დაშორება კონტენტსა და საზღვარს შორის.
   - **Border:** საზღვარი/ჩარჩო, რომელიც გარს ერტყმის padding-ს.
   - **Margin:** გარე სივრცე, რომელიც ამ ელემენტს აშორებს მეზობელი ელემენტებისგან.
3. თითოეულ შრეს მიუწერე მოკლე განმარტება ადამიანურ ენაზე (მაგალითად: *„Padding — შიდა სივრცე, Margin — გარე სივრცე*).

### ნაწილი 3 — დიდი დუელი: Content-Box vs Border-Box (მთავარი ნაწილი)

1. შექმენი სექცია სათაურით: **„დიდი დუელი: Content-Box vs Border-Box“**.
2. განათავსე ორი ბარათი ერთმანეთის გვერდით (მაგალითად, Flexbox-ის გამოყენებით).
3. **ორივე ბარათს CSS-ში მიანიჭე იდენტური საწყისი პარამეტრები:**
   - სიგანე: `width: 300px`
   - შიდა დაშორება: `padding: 20px`
   - საზღვარი: `border: 5px solid ...`
4. **განსხვავება:**
   - **ბარათი A:** მიანიჭე `box-sizing: content-box` (ბრაუზერის დეფოლტ ქცევა).
     - ბარათის შიგნით ტექსტურად ახსენი, რომ მისი რეალური სიგანე ეკრანზე გახდა **350px** ($300 + 20\times2 + 5\times2$).
     - დაწერე ფორმულა: `საბოლოო ზომა = Width + Padding + Border`.
   - **ბარათი B:** მიანიჭე `box-sizing: border-box`.
     - ბარათის შიგნით ახსენი, რომ მისი რეალური სიგანე ეკრანზე დარჩა ზუსტად **300px**, რადგან padding და border „ჩაიფუთა“ მითითებული სიგანის შიგნით.
     - დაწერე ფორმულა: `საბოლოო ზომა = Width`.
5. ვიზუალურად ნათლად უნდა ჩანდეს, რომ ბარათი A გაცილებით განიერია, ვიდრე ბარათი B, მიუხედავად იმისა, რომ კოდში ორივეს `width: 300px` უწერია!

### ნაწილი 4 — პრაქტიკული პრობლემა: „რატომ ტყდება Layout-ი?“

1. შექმენი სექცია სათაურით: **„რატომ ტყდება განლაგება?“**.
2. აჩვენე რეალური ცხოვრებისეული მაგალითი:
   - შექმენი კონტეინერი (მაგალითად, ფიქსირებული სიგანით ან 100%-ით).
   - შიგნით ჩასვი 2 სვეტი, რომელთა სიგანეც არის `50%` და `50%`.
   - ორივე სვეტს დაამატე `padding: 20px` და `border: 2px solid ...`.
3. აჩვენე ორი ქეისი:
   - **ქეისი 1 (Content-Box):** padding-ისა და border-ის გამო სვეტების ჯამური სიგანე აჭარბებს 100%-ს, რის გამოც მეორე სვეტი ვარდება ქვემოთ (Broken Layout).
   - **ქეისი 2 (Border-Box):** `border-box`-ის წყალობით სვეტები ინარჩუნებენ ზუსტად 50%-ს და მშვიდად ეტევიან ერთ ხაზზე.

### ნაწილი 5 — შეჯამება და ოქროს წესი (Best Practice)

1. შექმენი დასკვნითი პატარა ბლოკი.
2. აჩვენე ცნობილი CSS წესი, რომლითაც თითქმის ყველა დეველოპერი იწყებს პროექტს:
   ```css
   *, *::before, *::after {
     box-sizing: border-box;
   }
   ```
3. მოკლედ (1-2 წინადადებით) დაწერე დასკვნა: რატომ გვიმარტივებს ეს წესი ცხოვრებას.

## დამატებითი გამოწვევა (სურვილისამებრ)

თუ გინდა შენი პრეზენტაცია კიდევ უფრო ცოცხალი და დახვეწილი გამოვიდეს:
- დაამატე მარტივი CSS ეფექტები — მაგალითად, `:hover`-ზე ბარათის ოდნავ წამოწევა (`transform: translateY(-5px)`) ან ჩრდილის გაზრდა (`box-shadow`).
- ფერები შეარჩიე გემოვნებით — გამოიყენე თანამედროვე, თვალისთვის სასიამოვნო ფერთა პალიტრა.

## ჩაბარების პირობები

- დავალება შესრულებულია მხოლოდ **სუფთა HTML და CSS**-ით.
- კოდი განაწილებულია ცალკე ფაილებში: `index.html` და `style.css`.
- კლასების სახელები არის ინგლისურ ენაზე, სემანტიკური და ლოგიკური (მაგ. `.box-model-demo`, `.card--content-box` და ა.შ.).
- CSS კოდში გამოყენებულია კომენტარები, სადაც მოკლედ არის ახსნილი ძირითადი ლოგიკა.
- დავალება გამოაგზავნე გიტჰაბის რეპოს სახით სადაც მითითებული იქნება პროექტის ლაივ ლინკი.
